# HTML Slides：编辑部风网页演示文稿

以 1280×720 舞台制作 16:9 HTML 课件，随窗口等比缩放。默认暖纸底、深红强调色、宋体标题、黑体正文与简洁页眉页脚；已有课件沿用用户确认的设计。参考模板 `assets/template.html`，组件见 `references/components.md`。

## 先明确这份课件给谁看

- 学生或听众是对外正文的读者。教师内部斟酌、制作提示、需拍截图的占位、版本争论和备课分工放内部文档；不能藏在公开 HTML 注释或讲者备注里一并上传。
- 区分内部决策过程和学生应知的不确定性：作业提交日期待定、未公布的评分比例等可按实际通知口径写明；不能替教师定数字，也不能把已经公布的总评构成误删。
- 用户已明确的署名、考核、分 Part、用图和发布要求直接执行。材料存在关键缺项时聚焦询问；不能因页数超过某个阈值重新要求整份审批。
- 先写简短计划：受众、核心结论、各 Part 回答的问题、逐页内容与引用。Part 按论证划分，内容迁移后更新全局结构，不能固定套三部分。

## 封面与目录不是收尾装饰

制作或重排时读 [references/cover-and-navigation.md](references/cover-and-navigation.md)。

- 系列课的单讲封面：本讲题目作大标题，“课程名 · Week N”作副标题；独立讲座突出讲座名。再安排讲者、单位和已提供的可点击课程网站；品牌色与署名按用户的参考。不要默认堆上各段授课分钟数或教师的组织方案。
- 多 Part 课件每个 Part 以深红章节隔页（`s-div`）开头，右侧列出全部 Part 并高亮当前。不另设总目录：封面后的第一张隔页兼作总目录，☰ 与 T 回到这一页。点其他 Part 跳到它的隔页，列表从原位置平滑移过去（约 1 秒）；点当前项进入正文。名称与顺序来自同一份 parts 数据。
- 内容用稳定 ID，`part` 表示归属，顺序单独维护；构建后再算显示页码与跳转链接。移动页面不能误改作业编号、周次、表格值或图片文件名。
- 附二维码时使用可扫描的真实素材，二维码本身及文本入口都能点击；链接适合听众实际使用。

## 图像与数据图

生成或更新配图、决定图像压缩方案时读 [references/gpt-image-infographics.md](references/gpt-image-infographics.md)。

- 叙事性流程、能力地图、人机协作可以由 **Codex 内置 GPT Image** 生成主体信息图。数据曲线和要求精确/可编辑的图表用标准绘图库或 SVG；真实软件截图不要生成。
- 用户说“主体用信息图”，就让图片承担主体解释；保留 HTML 标题、来源与一句落点，避免图片旁再堆完整文字列表。
- Prompt 要写明角色、视觉重点、逐条连线方向与反馈环；生成后检查中文、箭头、主次和未经要求的数字。图像里的示意数字不能伪装成论文实证数据。
- **图内配色与页面分开**：页面只用深红一个强调色；信息图内部用蓝、紫、橙、绿等对比色块区分模块与流程站点，深红只标主线箭头、回路和核心落点。分色规则同时写进共享锚点和逐站点描述，默认锚点见图像指南。
- **课件大图与网站缩略图使用不同策略**：中文信息图优先保留原尺寸与细节；列表图使用有高分屏余量的高质量 WebP。检查浏览器实际加载文件，避免框架二次压成低清图。
- 每个采用的图留原稿与 prompt，复制进项目后再引用。不要自动切换其他生成模型，也不要把包含 base64 的整份工具结果打印为文本。

## 制作与维护

1. **新课件**可复制 `assets/template.html`。**已有课件**先定位生成源与资源清单，不覆盖成空模板；改源文件再重建，并核对最终 HTML。
2. 页眉、页脚、标题、来源与正文保持清楚的层级。参考 `references/components.md`，先用用户已确认的页面结构，不为了增加页型而打散论证。
3. 每个入场元素使用 `data-a`；非封面类内容页的 kicker、标题与短横线风格统一。页脚 `data-k` 与当前 Part 一致。
4. 按语义强调：同级项目可平权；用户要求突出智能体、人机协作或核心结论时，要在画面位置、面积与颜色上可见。每页少量深红，不给所有项目同样的强强调。
5. 投影正文宁可拆页或压缩文案，不靠缩小字号装满。长标题优先保持用户措辞，通过断行与布局处理；需要改变标题含义时再与用户对齐。
6. 数字按性质处理：日期、周次、作业编号、权重与 benchmark 分数保持核验值；概数只在不损失信息时使用，不能随意加“+”。未经确定的比例不上固定数字。无信息量的强调词删去，规则中的排他词保留。

## 外置媒体与网页导航

```text
html_deck_<主题>/
├── index.html
├── images/ 或 assets/      该课件实际使用的资源
└── review/                内部审阅记录，发布时排除
```

- 不将大图或视频 base64 内嵌进 HTML。使用相对文件路径，保持本地与网页版本可用。
- 懒加载在 `go()` 中加载当前页与相邻页；从某页离开时暂停视频。提供 `hashchange` 处理，既能点目录，也能从 `#页码` 直达。
- 已有源中的懒加载/事件监听先检查再扩展，避免叠加两份监听。基础模板已带 `hashchange` 入口（支持 `#页码` 与 `#内容ID`）、相邻页懒加载、离页暂停视频与隔页间转场，T 键与 ☰ 按钮回第一张隔页；旧课件缺这些时补齐，详见封面与目录参考文档。
- 面向学生发布后，材料导航使用实际可打开的线上 URL，外链 `target="_blank" rel="noopener"`。同步修改构建片段及本地成品，不能只修网站副本。
- 不直接公开整个工作目录。发布实际引用的资源，排除教师 notes、制作计划、原始问卷、内部审计和临时稿。

## 截图与交互审阅

使用当前环境可用的 Playwright 或浏览器自动化工具；操作细节见 [references/review-checklist.md](references/review-checklist.md)。

- 新建课件逐页审阅；窄范围修改复查改动页，重排还要复查全部目录及各部分首页。
- 等字体、图片和动画结束，检查 1280×720 投影版；大图清晰度再看高分屏或放大效果。用图片 `naturalWidth` 与实际下载大小确认，不能从扩展名猜质量。
- 每个目录面板都实际点击，核对 active slide、标题、页码与 Part；另查键盘、直达 hash、重排后的跳转。
- 检查源数据、图内箭头和说明文字，而非只看画面美观。成绩图不能出现未定细分比例；公开版不能带教师内部记录。
- 网站发布后核验每个材料入口与资源响应，检查内容而非仅 200 状态；使用 Range 时正常结果可能为 206。
- 记录发现、修复与剩余限制。停止本任务创建的预览服务，不用宽泛的 `pkill` 关闭别人的服务。

## 按需导出

用户需要 PDF 或可编辑 PPTX 时，使用现有 `scripts/export_deck.py`。导出步骤与边界见 [references/export.md](references/export.md)。不因修改 HTML 而自动生成未请求的导出文件。

## 品牌色

默认 `--brand` 为深红，配套 `--brand-deep` 与 `--brandwash`；更换时一起检查封面标题、目录高亮和链接。已有用户模板与明确参考优先于默认色。深红页（`data-dark`）上正文用白色、透明度不低于 .88，米色 `#F8E8D0` 标当前项与罗马数字；换品牌色时同步检查这几处对比度。
