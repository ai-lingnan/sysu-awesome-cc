# 封面、分 Part 与可点击目录

## 封面先交代身份与入口

封面的主要层级是：课程或演讲名称 → 本次主题/教学周 → 讲者及所属单位 → 已提供的课程网站或资料入口。系列课的单讲例外：本讲题目作大标题，“课程名 · Week N”作副标题（W02 按教师要求改成这样），课程名放眉头或页眉也可以。没有入口时省略，不虚构链接。优先使用用户给出的品牌色与参考页；课程名不能被日期、课时安排或装饰抢走注意力。署名按本次明确口径，不从旧模板复制人员名单。

- 网站显示人能读懂的短地址，并可点击打开新页。机构名称较长时，讲者名与机构分行排；先看实际投影效果，再调留白。
- 不默认把各部分时长、教学组织方案、制作备注放上封面。需要的议程放目录页；用户明确需要的时间信息才显示。
- 作者/课程资源页与封面职责不同。资料较多时，独立放资源页；二维码图本身包在 `<a target="_blank" rel="noopener">` 中，旁边提供文本入口。公众号若没有可直接访问的主页，点击可打开二维码大图，不虚构跳转 URL。
- 外部署名或机构信息需以用户提供的参考及实际来源为准，不把某一位讲者的署名写成通用模板默认值。

## 先分论证，再分章节

读完整份内容，为每个 Part 写一句“它回答什么问题”，再写前后两部分的承接关系。Part 数量由内容决定，不能为了三栏模板硬凑三部分。

W01 的实际结构可作为例子：

| Part | 回答的问题 | 收入的内容 |
|---|---|---|
| 课程与考核 | 学什么、怎样算学会？ | 目标、课堂、作业与项目 |
| 智能体的发展与能力 | 从哪里来、能做到哪一步？ | 发展、能力证据、工具选择与套餐 |
| 反思人与 AI 分工 | AI 越能干，人该投入什么？ | 选题、理解、判断、品味与上下文 |
| 环境准备与上机 | 如何亲手完成一个任务？ | 安装、跟做、验收与排错材料 |

其中“精力投在哪里”是一个独立论证，不应被吞进技术发展史；工具与价格选择依赖前面介绍的能力，放在能力部分末尾更连贯。后续课程不必照抄这四部分。

W02 初稿按三部分写，教师要求再细分，最终为七部分：看懂智能体 / 两个 Agent 底层约束 / 权限与数据安全 / 初始化项目 / 最佳人机会话原则 / CLAUDE.md / 完成一轮协作。判断标准：一段内容回答的是一个独立问题（如权限与数据安全），就单独成 Part，让学生在转场页看到话题换了。细分时只在 parts 数据里加项、插入新隔页，旧内容 ID 不变。

## 章节隔页兼作目录

多 Part 课件每个 Part 开头放一张章节隔页，右侧列出全部 Part 并突出当前部分；不另设总目录，封面后的第一张隔页兼作总目录，☰ 与 T 回到这一页。列表名称与顺序由同一份数据生成，避免各页各改各的。隔页落点用听众能理解的问题或主题，别放教师的教学设计理由。

列表每项整行可点击，使用语义化 `<a>`，支持 Tab 与 Enter，有可见焦点。点其他 Part 跳到它的隔页，伴随平滑转场；点当前项进入本部分第一页正文（构建时用 `positions[home_id] + 1` 算目标，并断言那一页属于该 Part）。已有用户指定落点时沿用。

### 深红章节隔页与转场

模板默认：章节隔页 `s-div` 加 `data-dark`，运行时把页眉页脚、进度条和翻页按钮转白。样式来自 AI-CEO 二期 D1 html_deck_v8 的章节隔页，2026-09-14 在 W02 固化。

- 左侧写 `PART N / 总数`、部分名、一条短白线和本部分的一句落点；右侧 `.plist.divlist` 竖排全部 Part，当前项用米色竖条、浅底和稍大字号标出，每项可点。一页同时承担转场与目录。
- 不设单独总目录页。W02 依次试过浅色六卡总目录、深红六卡总目录、居中放大的列表，教师的反馈是：总目录后紧跟第一部分隔页，目录连着出现两次；从总目录点进去又看到一次目录；总目录也做成深红后，整份课件显得太重。最后定为封面后直接进入第一部分隔页。
- 隔页之间跳转有平滑转场：旧页留在底下，左侧内容淡出、列表隐去；新页透明底叠上，列表各项从旧位置按比例移到新位置（FLIP，约 1 秒），选中项渐变为米色高亮，左侧标题与罗马数字随后浮现；两页圆环同位，不重播。实现见模板 `morph()` 与 `.morph-in` / `.morph-out`。列表内部尺寸用 em，缩放才成比例；新页左侧内容延后约 520ms 入场，避免列表横穿标题；转场中再换页先收尾清掉内联样式；系统设为减弱动效或根元素带 `.no-motion` 时不播放。
- 列表项不换行，右栏 350px；当前项放大后最长的部分名仍须一行放下（W02 的“两个 Agent 底层约束”曾在 330px 栏里断成两行）。
- 右侧列表其余项保持白色 .88，不用低透明度区分已讲、未讲：红底上 .6 的白字约 3.5:1，教室后排读不清。
- 描边罗马数字放左下、从左滑入；同心圆环在右上、放大淡入。圆环是定位伪元素，会盖住未定位的正文块，正文块要加 `position:relative`（模板已处理）。
- 整页深红只用在隔页上，每 8–10 页出现一次已经足够醒目；其他页再做成整页深红，整体会显得重。

### 内容身份与显示页码分开

推荐维护：

- `pages.json`：稳定 `id`、标题、`part`、正文与内部讲稿。
- `slide_order.json`：按显示顺序排列的内容 ID。
- `parts` 数据：部分名称、简介、首页 ID。

构建学生版时只序列化公开字段；内部讲稿可以留在源数据，但不得把整份含讲稿的 `pages.json` 放入 public 或内嵌 HTML。

在构建完成后由顺序解析目录目标：

```python
positions = {content_id: index + 1 for index, content_id in enumerate(order)}
assert len(positions) == len(order)
for part in parts:
    assert part['home_id'] in positions
    part['href'] = '#' + str(positions[part['home_id']])
```

不要把 `#17` 等旧页码散落到每个面板，也不要通过全局替换数字重排文稿。页码、作业编号、教学周、表格数值、素材文件名各有身份；移动页面只改变顺序和显示页码。

### 点击不能只改变地址栏

基础模板用 `hashchange` 统一入口：链接点击、浏览器后退、`#页码` 与 `#内容ID` 直达都调用 `go()`；`go()` 用 `replaceState` 把地址改成 `#页码`，不会触发循环事件。

```js
function readHash() {
  const h = decodeURIComponent(location.hash.slice(1));
  if (/^\d+$/.test(h)) return Number(h) - 1;
  return Math.max(0, slides.findIndex(s => s.dataset.id === h));   // 无效值回封面
}
addEventListener('hashchange', () => go(readHash()));
go(readHash());
```

`go()` 对非法/越界数值做有限数检查并限界；将目标页及相邻页的 `data-src` 物化；离开某页时暂停其中的视频；非当前页设 `inert` 与 `aria-hidden`。☰ 与 T 的目标用 `slides.findIndex(s => s.classList.contains('s-div'))` 动态求得，不写死 `go(1)`，封面后插页也不会指错。改旧课件先检查已有实现，避免再加一套监听或并存两份状态。

验收：每一张隔页的每个列表项实际点击一次，当前项与其他项分别核对去向；确认 `.slide.active`、标题、页码、部分名均匹配，而不是仅看 `href`。重排后复查全部隔页、章节页脚、摘要导航及用户特别指定的页。
