# GPT Image 信息图与图片交付

## 选择画法

| 内容 | 适合的做法 |
|---|---|
| 精确 benchmark 曲线、坐标、数据表、可编辑标签 | 基于核验数据，用标准绘图库或 SVG，保留数据与来源 |
| 动作过程、能力地图、人机协作、具体物件叙事 | Codex 内置 GPT Image；可以让主体内容整块成为信息图 |
| 真实产品界面、人物、机构二维码 | 使用核实过的原始素材，不让模型伪造截图或可扫描二维码 |
| 图内数字只是帮助理解的例子 | 标明“示意”，不能把生成的数字挂在论文来源下当成实证结果 |

当用户要求某页主体用信息图，应重构正文层级，让图片承担解释任务；不是在原来满屏文字旁边再塞一张装饰图。保留 HTML 标题、来源与一句落点，图内不再重复大标题。

## 内置 GPT Image 路线

1. 使用当前环境的内置图像生成工具，按其 schema 调用。一张独立素材对应一个独立请求。没有 `aspect_ratio`、`size` 或目标路径字段时，在 prompt 说明要求，不编造工具参数。
2. 记录素材 ID、用途、完整 prompt、原图路径、采用版本与部署路径。并行生成可以提高效率，但以可持续审阅的批量执行。W02 的做法可直接沿用：`review/image-prompts.json` 存共享 `style` 锚点与每张图的 `content`；`review/assets.json` 存拼好的完整 prompt、原图与上一版原图路径、`edit_prompt`、部署路径、宽高、字节数与 sha256。两份都在 `review/`，不随学生版发布。
3. 新图不带不存在的参考图参数；编辑现有图先查看原图，并按工具规范传入引用。
4. 不将整份结果对象输出为文本——其中可能含巨大的 base64 `image_url`。将图交给原生图片展示接口，文字只输出素材 ID 和工具返回的路径提示。长调用期间按环境允许的方式继续提供简短进度。
5. 内置生成失败时保留已完成素材，说明失败项；不要静默切 CLI/API、其他模型或 Gemini。需要替代路线时按本轮已有授权处理。
6. 生成后看图：中文是否正确、箭头有无反向、主次是否对应论点、是否擅加数字/徽标/大标题。修图用内置图像编辑；格式转换与压缩在用户要求和交付需求范围内使用图片工具。
7. 采用的素材复制进项目，不能让成品依赖生成缓存路径。保留原图；审阅记录、prompt、内部推敲不随学生版一起公开。

## Prompt 要写清什么

- 受众与一句话结论；每个板块的角色、物件及少量精确标签。
- 主视觉是谁：例如人定义目标与验收，智能体执行和反馈。想突出“智能体与人机协作”，必须明确面积、位置、颜色和连线，不能只在旁边放两个人物图标。
- 连线源点、终点、箭头方向，串行步骤与反馈环分别描述。四步循环要写成“顶部从左到右；最后一步沿底部返回第一步”，生成后逐段核对。
- 宽高比与正文槽位：1280×720 的课件中，21:9 横图放入约 420px 高的图框是已验证的起点；不是所有页必须用同一尺寸。
- 简体中文标签保持短、疏、大，强调“无整体大标题”。精确数据不要交给生成模型排版。

### 可复用例子：工具使用

> 为无编程基础的本科生画 21:9 信息图，暖纸底、手绘线条与水彩，四个阶段各用一种色块区分，深红只画主线箭头与回路，无整体大标题。四个阶段从左到右：“想一步”（蓝色，大脑，需要查公司营收）→“做一步”（橙色，机械手操作搜索、文件夹、终端）→“看结果”（绿色，数据或错误消息）→“再决定”（紫色，继续、修改或完成）。顶部箭头均向右；最后一步沿底部向左返回，再向上指入第一步，标签“根据观测继续推理”。少量大号中文；不生成具体财务数字。图片主体突出模型、工具与观测反馈的联系。

## 图内配色：模块用对比色区分，深红留给重点

页面与图内是两套配色逻辑。HTML 页面只有一个强调色（深红 `--brand`）；信息图内部用几种对比明显的色块区分流程站点、并列区域或不同角色，让学生一眼分出“这是第几站”“这块与那块不同”。这条是 W02 教师明确提出的要求。按旧锚点生成的 harness、context-layers 两张图，都靠修图才把分色加回去，多花了一轮。

| 图内元素 | 用色 |
|---|---|
| 同级模块、流程站点、并列区域 | 蓝、紫、橙、绿等色相分明的水彩色块，每块一种；块标题用同色加深 |
| 主线箭头、回路、核心落点 | 深红 `#A5171C` |
| 底色 | 暖纸白 `#FBFAF7`，与页面一致 |
| 反例、错误做法 | 深红叉号或灰色，不占用模块色 |

- 同一项目内，模块色按语义固定，不按位置轮换。W02 里模型与上下文用蓝、权限用紫、工具用橙、结果与状态用绿，跨图复现时学生靠颜色认出同一个东西。
- 色块之间留足色相差，投影下能分开。可以低饱和，同一张图里不要出现两种相近的蓝。
- 深红不铺整块背景，只用于线条、边框、标签和一两处强调。全图都是深红时，强调就失效了。
- 两块代表对立关系时（约束与方法、旧做法与新做法），用一冷一暖，例如蓝与橙。
- 模块超过 5 个时，先检查该不该拆图；第六种颜色开始难以区分。

**写进 prompt 的两处**：正文逐站点写明颜色，如「第一站（蓝色）」「第二站（紫色）」；共享锚点里写分色规则。只写一处，模型容易忽略。

### 课件信息图默认锚点

每张图的 prompt = 本图内容描述 + 下面这段锚点。锚点在项目里存为一个字段，全部素材复用；个别图要调颜色时改内容描述，不改锚点。

> 教学信息图，面向无编程基础的本科生。超宽 21:9 横图，尽量 2520×1080 或更高原生分辨率。暖纸白底 #FBFAF7。不同模块、流程站点或并列区域分别用色相分明的低饱和水彩色块区分（如蓝、紫、橙、绿），每块标题用同色加深；深红 #A5171C 只用于主线箭头、回路与一处核心强调，不铺满整块。精细铅笔线条，编辑部手绘插画风，物件具象、留白充足。简体中文大字标签清晰端正，每个标签 2–8 字。无整体大标题、无水印、无徽标、无页码、无装饰机器人，不添加任何未经指定的数字。连线不穿过文字。图承担课件主体讲解，适合投影。

W02 早期锚点写的是「深红强调重点，辅以少量低饱和橙色与蓝色水彩」，把彩色定位成陪衬，与模块分色的要求相反，新项目不要沿用。prompt 里写 2520×1080，W02 实际得到约 1915×821，按实际尺寸验收。

### 用户指定 /image-gen 时

`/image-gen` 自带的风格锚点是公众号用的橙蓝双主色，与上面的规则冲突。用户要求用它出图时，用本节锚点替换它的默认锚点，并指定 `--aspect-ratio 21:9`。该脚本 21:9 输出 1536×658，低于 W01、W02 约 1900px 宽的验收经验，细线与中文标签要在投影截图里确认。

## 清晰度与体积分场景处理

**课件主体图**：全屏文字、细线与箭头需要高分辨率。保留原尺寸，W01 约 1900px 宽 PNG 的效果已通过投影截图检查。不要统一缩成 1200px WebP q85。含精细中文的信息图以原尺寸 PNG 或通过实际对比的无损格式为起点；如需进一步压缩，先生成独立派生版，放到真实页面看全屏和高分屏效果再决定。用户明确要求原尺寸 PNG 时遵循该要求。

**网站列表缩略图**：不应让每个 96×64 的位置下载 2MB PNG。原图留本地，以显示尺寸和设备像素比留余量。W01 验证的参数为 **480×320 WebP、quality 90、effort 6**，每张约 10–18KB；这是该组图的结果，不承诺所有图片同样体积。

检查完整链路：原图 → 派生图 → 框架图像优化 → 浏览器 `currentSrc` / `naturalWidth`。已经预处理的 480px WebP 应避免再次被 Next Image 降到 96px / q75；可对这组素材使用 `unoptimized`，此时仍然交付小体积 WebP，而非原始 PNG。既不要用“全上原图”解决模糊，也不要凭文件小就认为合格。

照片、视频、截图各自选择编码方案，不把缩略图参数套到课件。保留真实扩展名，不将 JPEG/WebP 改后缀冒充 PNG。

## 装页与检查

使用外置资源和相对路径。模板已定义 `.figbox > img.figimg`（约 410px 高图框、`object-fit: contain`，JPG 用 `mix-blend-mode: multiply` 融进纸色），并在注释里给了一张 `s-fig` 主体信息图页的完整标记；跨整行的主体图直接复制它，双栏时放进 `.row > .fig`。旧课件没有这组样式时先补上，再做截图验证。页内标题与落点仍是 HTML，可编辑、清楚，不随图片压缩。使用 `data-src` 时确认目标页及相邻页预加载，`#页码` 直达也要触发加载。

截图需等图片 `complete && naturalWidth > 0` 及入场动画结束。检查全图没有裁切、中文可读、落点不压页脚、箭头能顺着读。替换素材同时更新生成源、图片清单和发布副本，不能只改最终 HTML。
