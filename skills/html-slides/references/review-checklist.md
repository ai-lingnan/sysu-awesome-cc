# 截图与交互审阅

## 运行方式

用当前环境可用的浏览器工具（Playwright CLI、MCP 或其他已授权浏览器接口）。不硬依赖某个旧工具名称。

如工具不支持本地文件，启动绑定 `127.0.0.1` 的临时 HTTP 服务并记下 PID；使用空闲端口。服务根只包含待审课件，避免把整个备课目录暴露出去。Python 解释器按本机项目环境约定选择。

- 投影审阅：1280×720；高清信息图另外在高分屏/放大状态看中文与细线。
- 新课件逐页截图；内容较窄的修改复查改动页。重排后复查各部分首页和所有目录跳转。
- 等图片 `complete && naturalWidth > 0`，再等入场动画结束；模板动画约1.6秒，但以实际状态为准。
- 修改源后重建，再刷新页面。缓存检查可加版本 query；单独改 hash 不保证取到新的 HTML。
- 支持 hashchange 的运行时应允许 `#页码` 直达与目录点击；旧版没有监听时需刷新加载，制作时应补齐，不能长期把交互缺陷当成测试限制。
- 有的预览面板打开项目外的 `file://` 页面时只渲染静态快照，`#页码` 不生效，截到的始终是封面。遇到这种情况改用 Playwright：每个页码先 `goto` 再 `reload`，等入场动画结束后截图。
- 用户说“没看到变化”时，先核对磁盘上 index.html 的修改时间和一段新内容的特征字符串，再请对方强制刷新（Mac 上 Cmd + Shift + R），并确认对方看的是哪一页。

## 每张页面

- [ ] 没有侵入页眉/页脚，也没有导航按钮遮挡主体；按实际模板安全区判断。
- [ ] 标题、中文与来源无截断，图片没有裁掉说明，文字层级可读。
- [ ] 图内箭头符合真实顺序，反馈箭头确实指回下一轮起点；没有多余箭头或自循环冒充步骤。
- [ ] 图中视觉主次符合论点，要求突出的人/智能体/协作关系看得见；并列内容没有无理由的大小差别。
- [ ] 图内模块、流程站点用对比色块区分，同一概念跨图同色；深红只在主线、回路与核心强调，没有铺满整张图。
- [ ] 没把生成的示意数字当成真实 benchmark、营收或调查结果。引用、日期和数值与源表一致。
- [ ] 页内大标题没有在信息图里再重复；图片主体与保留的落点不互相复述整段文字。
- [ ] 信息过多时拆页或精简，不把正文压成小字。长标题的断行不拆散词义。
- [ ] 删除没有信息量的绝对化修辞；保留事实边界、日期、编号、成绩构成与规则。
- [ ] 学生版没有“待制作”“教师考虑”“方案取舍”等内部说明；评分细分未确定时不出现固定数字。

## 封面与全局

- [ ] 封面的大标题、品牌色、讲者及单位与用户指定一致；网站可点击；没有不必要的授课时间条。
- [ ] 资源页二维码可扫描，二维码本身和文字链接可打开正确目标。
- [ ] Part 数量与论证结构相符；封面后是第一部分隔页（兼作总目录），各部分开头的隔页高亮本部分。
- [ ] 所有目录的部分名称、顺序和简介一致；总页数、页脚部分名与页面顺序匹配。
- [ ] 章节隔页的页眉页脚与翻页按钮已转白；白字透明度不低于 .88；右侧高亮的是本部分；放大的当前项仍一行放下，罗马数字（如 III）不溢出。
- [ ] 隔页之间点击跳转有平滑转场，结束后没有残留 `.morph-in` / `.morph-out`；转场中连点、按 T、浏览器后退不出现白底闪烁，列表不停在半路。
- [ ] 内容ID、作业编号、周次、数据值、素材编号没有因插页而被重编号。
- [ ] 对外版不含内部 speaker notes、HTML 注释中的备课讨论或内部文件链接。

## 必须实际操作的导航

1. 每份目录的每个面板用点击进入一次，比较 `.slide.active`、显示页码、标题和 Part。
2. Tab/Enter 可以访问目录面板，焦点可见。
3. 从URL直接访问封面、一个部分首页和一个图片页；回退与无效hash不会白屏。
4. 方向键、滚轮/触摸（已提供时）、进度条各抽查一次；输入控件内操作不应误翻页。
5. 最后一页的材料链接打开对应线上学生文档，不能仍指 `file://` 或本地 `.md`。

## 图像链路

- [ ] 课件中文信息图保留足够原生像素；全屏细线清楚。不得因为文件变小就认为压缩成功。
- [ ] 网站缩略图兼顾体积与高分屏清晰度；检查 `currentSrc`、`naturalWidth`、下载字节及格式。
- [ ] 没有“先做高质量WebP，又被框架降成96px”的二次压缩；也没有给小缩略图下载数MB原PNG。
- [ ] 懒加载在目录跳转/直达时也生效；目标页与相邻页资源已准备。
- [ ] 视频离页暂停；封面与首屏无需加载整份课件的大图。
- [ ] 部署资源有正常响应和正确内容类型，必要时核对文件散列；Range请求可返回206。

## 常见修法

| 症状 | 处理 |
|---|---|
| 点目录只变URL、不翻页 | 补统一hashchange入口，检查go()与链接映射 |
| 插页后目录或页脚错位 | 从稳定ID/part和实际顺序生成，不全局替换数字 |
| 中文信息图模糊 | 查看原图和浏览器实际文件，分开处理像素不足与有损压缩 |
| 缩略图过大或过糊 | 高质量小尺寸WebP留高分屏余量，避免二次优化 |
| 图内主次不明 | prompt明确核心角色的面积、位置、颜色及连线，再生成/编辑 |
| 图内全是深红、模块分不开 | 检查共享锚点是否仍是“深红强调、少量橙蓝陪衬”的旧写法；换成模块分色锚点，并在正文逐站点写颜色 |
| 反馈箭头方向反了 | 按每条边的起点与终点重写prompt或修正矢量图，再目检 |
| 内容挤进页脚 | 调整图框高度或拆分内容，不把全部字体缩小 |

记录实际发现与修复，保留必要截图。停止本任务的预览进程；清理范围限定为本任务创建的临时文件。
